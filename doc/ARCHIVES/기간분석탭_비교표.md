## 2. 백엔드 API 비교

### 2.1 현재 API vs 필요 API

```
현재:
├── GET /api/statistics/summary          (전체 통계, 캐시됨)
├── GET /api/statistics/detailed         (필터링 통계)
├── GET /api/flights/dates               (사용 가능 날짜 목록)
└── GET /api/flights/all                 (항공편 목록)

필요 (추가/수정):
├── GET /api/statistics/detailed (수정)
│   ├── 날짜 범위 파라미터 추가
│   ├── daily_breakdown 추가
│   └── hourly_heatmap 추가
│
├── GET /api/analytics/daily-summary (신규)
│   ├── 각 날짜별 L5/L4/L3 분포
│   └── 감지율 계산

├── GET /api/analytics/heatmap (신규)
```

## 3. 데이터베이스 변경 사항

### 3.1 테이블 구조 변경

```
similarities 테이블:
┌────────────────────────────────────────────┐
│ 현재 컬럼                                     │
├────────────────────────────────────────────┤
│ id (PK)                                     │
│ flight_id_1, flight_id_2 (FK)              │
│ callsign_1, callsign_2                      │
│ similarity_level                            │
│ similarity_score                            │
│ has_sector_overlap, total_overlap_minutes   │
│ detected_at (timestamp)                     │
└────────────────────────────────────────────┘
                     ⬇️ 추가
┌────────────────────────────────────────────┐
│ 추가되는 컬럼                                 │
├────────────────────────────────────────────┤
│ eobd (DATE) ← ⭐ 가장 중요                 │
│ route (TEXT) e.g. "ICN-GMP"                │
│ airline_1 (TEXT) e.g. "AAR"                │
│ airline_2 (TEXT) e.g. "DAL"                │
│ peak_hour (INTEGER 0-23)                   │
└────────────────────────────────────────────┘
```

### 3.2 인덱스 추가

| 인덱스명 | 대상 컬럼 | 용도 | 성능 개선율 |

## 4. 쿼리 성능 비교

### 4.1 현재 vs 개선 후

#### Before: 7일 데이터 조회 (약 10,500개 항공편)
```sql
SELECT
  s.callsign_1, s.callsign_2, s.similarity_level,
  f1.eobd, f1.dept_airport_cd, f1.dest_airport_cd
FROM similarities s
JOIN flights f1 ON s.flight_id_1 = f1.id
JOIN flights f2 ON s.flight_id_2 = f2.id
WHERE f1.eobd BETWEEN '2025-01-01' AND '2025-01-07'
  AND f2.eobd BETWEEN '2025-01-01' AND '2025-01-07';

-- 예상 시간: 8-12초 (JOIN 오버헤드)
```

#### After: 역정규화 + 인덱스 활용
```sql
SELECT *
FROM similarities
WHERE eobd BETWEEN '2025-01-01' AND '2025-01-07';

-- 예상 시간: 0.3-0.5초 (60-90% 개선)
```

### 4.2 집계 쿼리 성능

#### 일자별 집계
| 방식 | 쿼리 | 시간 | 개선율 |
|------|------|------|--------|
| **Before** | WITH JOIN | 4-6초 | - |
| **After (뷰)** | FROM v_daily_summary | 0.2-0.3초 | **95%** |

#### 노선별 집계
| 방식 | 쿼리 | 시간 | 개선율 |
|------|------|------|--------|
| **Before** | CONCAT + GROUP BY | 3-5초 | - |
| **After** | FROM v_route_summary | 0.1-0.2초 | **97%** |

## 6. 마이그레이션 영향 분석

### 6.1 기존 쿼리에 미치는 영향

```
✓ 호환성 유지:
  - 새 컬럼은 모두 DEFAULT NULL
  - 기존 WHERE 절 변경 없음
  - BACKWARD COMPATIBLE

⚠️ 마이그레이션 시간:
  - 기존 데이터 역산: O(N) 시간
  - 인덱스 생성: O(N log N)
  - 예상: 대규모 DB(>100만 레코드)는 몇 시간 소요

⚠️ 트랜잭션 관리:
  - UPDATE 중 테이블 잠금 가능
  - 야간 정기점검 시간에 수행 권장
```

### 6.2 서비스 다운타임

| 단계 | 작업 | 예상 시간 | 영향 |
|------|-----|---------|------|
| 1 | ALTER TABLE (컬럼 추가) | 1-2분 | 테이블 잠금 |
| 2 | UPDATE (데이터 역산) | 10-30분 | 쓰기 불가 |
| 3 | CREATE INDEX (인덱스) | 10-20분 | 읽기 느림 |
| 4 | CREATE VIEW (뷰 생성) | <1분 | 영향 없음 |

**총 다운타임 가능성:** 30-50분 (읽기 전용 모드에서 부분 영향)

```
  ├─ Phase 2: 백엔드 API 개발 (병렬)
  │  ├─ [Mon-Tue] 스키마 정의 및 리뷰
  │  ├─ [Wed-Thu] API 구현 (4개 엔드포인트)
  │  └─ [Fri] 통합 테스트
  │
  └─ Phase 3: 프론트엔드 개발 (병렬)
     ├─ [Mon-Tue] UI 목업 및 상호작용 설계

Week 4:
  ├─ Phase 4: 통합 테스트
```
